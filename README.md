# 약속 장소 판사

여러 명이 만날 때, 한 사람만 멀리 오지 않도록 공평한 약속 역을 정해 주는 웹앱입니다.
단톡 대화를 붙여넣으면 각자의 출발지를 정리하고, 이동시간을 계산해 가장 공평한 역을 법정 판결문 형식으로 알려 줍니다.

## 문제

친구 여럿이 약속을 잡으면 보통 "지도상 중간쯤"으로 장소를 정합니다. 그런데 지리적 중간이 이동시간까지 공평하지는 않아서, 한 명만 한 시간 넘게 오는 일이 자주 생깁니다. 장소를 정하기까지 단톡방에서 "어디서 와?"가 수십 번 오가는 것도 번거롭습니다.

같은 네 명(강남·건대입구·잠실·수원)을 예로 들면, 출발지 좌표의 중간에서 가장 가까운 역(강남)은 가장 먼 사람이 약 75분을 이동해야 합니다. 이 앱이 고른 역(판교)은 누구도 약 53분을 넘지 않습니다.

## 주요 기능

- **단톡 대화로 출발지 정리** — 대화를 붙여넣으면 AI가 참여자, 출발역, 약속 목적을 채웁니다. 30개 후보 역에 없는 지역(예: 일산)은 비워 두고 언급된 지명을 안내하며, 한 번 눌러 그 지명을 바로 검색할 수 있습니다.
- **예시 10개** — "예시 불러오기"를 누르면 서로 다른 샘플 단톡 10개가 섞인 순서로 하나씩 들어갑니다.
- **출발지 입력 두 가지** — 30개 역 목록에서 고르거나, 주소·장소 이름으로 검색해 정할 수 있습니다. 검색은 검색 버튼이나 Enter를 눌렀을 때만 실행합니다.
- **약속 목적** — 밥·카페·술·공부·놀거리 중 최대 3개를 우선순위대로 고르고, 이유를 짧게 적을 수 있습니다(최대 80자). 목적은 판결문 문장과 주변 장소 탭 순서에 반영되며, 역 순위에는 영향을 주지 않습니다.
- **출발 시각 안내** — 약속 시각을 넣으면 사람마다 "추정 이동시간 + 여유 5분"을 뺀 출발 시각을 보여 줍니다.
- **공평한 역 계산** — 30개 후보 역마다 사람별 이동시간을 계산해 순위를 매깁니다. 두 가지 기준을 토글로 바꿀 수 있고, 각 기준의 설명을 화면에 함께 보여 줍니다.
  - 가장 먼 사람 기준(기본): 가장 오래 걸리는 사람의 시간이 짧은 순, 같으면 사람 간 시간 차이가 작은 순 (분 단위로 반올림해 비교)
  - 전체 균형 기준: 가장 긴 시간 × 0.7 + 시간 차이 × 0.3 이 작은 순 (화면에는 점수를 보여 주지 않고 결과만 비교)
  - 기준을 이렇게 정한 근거(시설 입지 이론의 최소최대 원칙 등)는 [docs/CRITERIA.md](docs/CRITERIA.md)에 정리했습니다.
- **기존 방식과 비교** — 출발지 좌표의 중간에서 가장 가까운 역과 판결 역을 나란히 보여 줍니다.
- **판결문** — 계산 결과를 근거로 주문·판결 이유·선고 형식의 판결문을 만듭니다.
- **지도와 주변 장소** — 판결 역, 기존 방식 역, 출발지를 지도에 표시합니다. 판결 역 반경 500m의 카페·음식점·놀 곳을 보여 주고, 각 장소를 네이버 지도나 카카오맵에서 바로 열 수 있는 링크를 붙입니다.

## AI를 쓰는 범위

AI(Claude)는 두 가지만 맡습니다. 단톡 대화를 읽어 참여자·출발역·목적을 정리하는 일과, 계산 결과를 판결문 문장으로 옮기는 일입니다.

- 이동시간 계산과 순위 결정은 일반 코드가 하므로 같은 입력에는 항상 같은 결과가 나옵니다.
- 판결문은 JSON 스키마를 지정한 구조화 출력(주문·이유·선고)으로 받습니다. 판결문에 나온 "N분"이 계산값과 하나라도 다르면 그 판결문을 버리고 기본 문장(템플릿)을 보여 줍니다.
- AI가 채우는 출발역은 정해진 30개 역 중에서만 고르도록 제한했고, 목록에 없거나 애매하면 비워 두고 사람이 역 선택이나 주소 검색으로 정합니다.
- AI 키가 없거나 호출이 실패해도 템플릿 판결문과 직접 입력으로 끝까지 사용할 수 있습니다.

## 구조

```text
브라우저 (React + Vite)
  ├─ 계산: 이동시간 추정, 순위(가장 먼 사람 / 전체 균형 기준), 기존 방식 비교, 출발 시각
  ├─ 지도: Leaflet + CARTO Voyager 타일 (OpenStreetMap 데이터)
  └─ /api 요청 ─────┐
                     ▼
API 서버 (Node.js)
  ├─ POST /api/extract   단톡 정리      → Claude API
  ├─ POST /api/verdict   판결문         → Claude API
  ├─ GET  /api/geocode   주소·장소 검색 → OpenStreetMap Nominatim, 키가 있으면 카카오
  └─ GET  /api/places    주변 장소      → 미리 받아 둔 데이터, 없으면 OpenStreetMap / 카카오
```

- API 키는 서버에서만 읽습니다. 빌드 결과물에 키가 포함되지 않는 것을 확인했습니다.
- 주소 검색은 같은 검색어를 서버에서 캐시하고, Nominatim 호출은 약 1초에 한 번 이하로 제한합니다.
- 서버의 처리 로직은 HTTP 처리와 분리되어 있어 AWS Lambda 함수로 옮기기 쉽습니다.

## 실행 방법

Node.js 22 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. `npm run dev`는 화면과 API 서버(포트 8787)를 함께 실행합니다.

AI 기능을 쓰려면 `.env.example`을 `.env`로 복사하고 키를 넣은 뒤 다시 실행합니다. 키가 없어도 앱은 동작합니다.

```env
ANTHROPIC_API_KEY=Claude API 키
KAKAO_REST_API_KEY=카카오 REST API 키 (선택)
```

| 명령어 | 설명 |
|---|---|
| `npm run dev` | 화면 + API 서버 실행 |
| `npm test` | 자동 테스트 83개 (외부 API는 호출하지 않음) |
| `npm run build` | 배포용 빌드 |
| `node server/scripts/prefetch-places.js` | 주변 장소 데이터 다시 받기 |

## API

| 요청 | 설명 |
|---|---|
| `POST /api/extract` | `{ chat }` → 참여자별 `{ name, station }`, 목적. 목록에 없는 지역은 `station: null`과 `hint` |
| `POST /api/verdict` | `{ purpose, purposes?, purposeNote?, mode, participants, ranked }` → `{ order, reason, sentence }` |
| `GET /api/geocode?q=일산` | 주소·장소 검색. 수도권 결과 최대 8곳 `{ name, address, lat, lng }`, `source`는 `osm` 또는 `kakao` |
| `GET /api/places?station=판교&category=cafe` | 반경 500m 장소 목록 (`cafe`, `food`, `play`), 가까운 순 최대 15곳 |

실패하면 `{ ok: false, reason }`을 돌려주며, 화면은 이 경우 기본 판결문이나 직접 입력으로 넘어갑니다.


## 한계와 다음 단계

- 이동시간은 직선거리를 바탕으로 한 추정치입니다(직선거리 km × 2.5분 + 10분). 실제 지하철 노선과 환승을 반영하는 것이 다음 목표입니다.
- 주변 장소와 주소 검색은 OpenStreetMap 데이터라 일부 가게나 주소가 빠져 있을 수 있습니다. 카카오 키를 넣으면 카카오 데이터를 씁니다.
- 약속 목적은 판결문 문장과 주변 장소 탭 순서에만 반영되고, 역 순위에는 반영되지 않습니다.
- 이후 계획: 막차 시간 반영, 약속 날짜 맞추기, 메신저 챗봇 연동, AWS Lambda 배포.
