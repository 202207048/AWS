# 약속 장소 판사

여러 명이 만날 때, 한 사람만 멀리 오지 않도록 공평한 약속 역을 정해 주는 웹앱입니다.
단톡 대화를 붙여넣으면 각자의 출발역을 정리하고, 이동시간을 계산해 가장 공평한 역을 법정 판결문 형식으로 알려 줍니다.

## 해결하려는 문제

친구 여럿이 약속을 잡으면 보통 "지도상 중간쯤"으로 장소를 정합니다. 그런데 지리적 중간이 이동시간까지 공평하지는 않아서, 한 명만 한 시간 넘게 오는 일이 자주 생깁니다. 장소를 정하기까지 단톡방에서 "어디서 와?"가 수십 번 오가는 것도 번거롭습니다.

같은 네 명(강남·건대입구·잠실·수원)을 예로 들면, 출발지 좌표의 중간에서 가장 가까운 역(강남)은 가장 먼 사람이 약 75분을 이동해야 합니다. 이 앱이 고른 역(판교)은 누구도 약 53분을 넘지 않습니다.

## 주요 기능

- **단톡 대화로 출발역 정리** — 대화를 붙여넣으면 참여자와 출발역, 약속 목적을 채웁니다. 후보 역 목록에 없는 지역은 비워 두고 사용자가 직접 고르게 합니다.
- **공평한 역 계산** — 30개 후보 역마다 사람별 이동시간을 계산하고, 가장 오래 걸리는 사람의 시간이 짧은 순으로 정렬합니다. 같으면 사람 간 시간 차이가 작은 역을 앞에 둡니다. 가중 점수 방식(최대 시간 × 0.7 + 시간 차이 × 0.3)으로 바꿔 비교할 수도 있습니다.
- **기존 방식과 비교** — 출발지 좌표의 중간에서 가장 가까운 역과 나란히 보여 줘서 차이를 확인할 수 있습니다.
- **판결문** — 계산 결과를 근거로 주문·판결 이유·선고 형식의 판결문을 만듭니다.
- **주변 장소** — 판결된 역 반경 500m의 카페, 음식점, 놀 곳을 보여 줍니다.

## AI를 쓰는 범위

AI(Claude)는 두 가지만 맡습니다. 단톡 대화를 읽어 출발역을 정리하는 일과, 계산 결과를 판결문 문장으로 옮기는 일입니다.

이동시간 계산과 순위 결정은 일반 코드가 하기 때문에 같은 입력에는 항상 같은 결과가 나옵니다. 판결문에 나온 "N분"이 계산값과 하나라도 다르면 서버가 그 판결문을 버리고 기본 문장을 대신 보여 줍니다. 출발역 역시 정해진 30개 역 중에서만 고르도록 제한했고, 애매하면 사람이 선택합니다.

## 구조

```text
브라우저 (React + Vite)
  ├─ 계산: 이동시간 추정, 순위, 기존 방식 비교
  ├─ 지도: Leaflet + OpenStreetMap
  └─ /api 요청 ─────┐
                     ▼
API 서버 (Node.js)
  ├─ POST /api/extract   단톡 정리      → Claude API
  ├─ POST /api/verdict   판결문         → Claude API
  └─ GET  /api/places    주변 장소      → 미리 받아 둔 데이터, 없으면 OpenStreetMap / 카카오
```

- API 키는 서버에서만 읽습니다. 빌드 결과물에 키가 포함되지 않는 것을 확인했습니다.
- Claude 응답은 JSON 스키마를 지정한 구조화 출력으로 받아, 화면에 들어갈 형식이 항상 일정합니다.
- 서버의 처리 로직은 HTTP 처리와 분리되어 있어 AWS Lambda 함수로 옮기기 쉽습니다.
- AI 키가 없거나 호출이 실패해도 기본 판결문과 직접 입력으로 끝까지 사용할 수 있습니다.

## 실행 방법

Node.js 22 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. `npm run dev`는 화면과 API 서버(포트 8787)를 함께 실행합니다.

AI 기능을 쓰려면 `.env.example`을 `.env`로 복사하고 키를 넣은 뒤 다시 실행합니다.

```env
ANTHROPIC_API_KEY=Claude API 키
KAKAO_REST_API_KEY=카카오 REST API 키 (선택)
```

| 명령어 | 설명 |
|---|---|
| `npm run dev` | 화면 + API 서버 실행 |
| `npm test` | 자동 테스트 (외부 API는 호출하지 않음) |
| `npm run build` | 배포용 빌드 |
| `node server/scripts/prefetch-places.js` | 주변 장소 데이터 다시 받기 |

## API

| 요청 | 설명 |
|---|---|
| `POST /api/extract` | `{ chat }` → 참여자별 `{ name, station }`, 목적. 목록에 없는 지역은 `station: null`과 `hint` |
| `POST /api/verdict` | `{ purpose, mode, participants, ranked }` → `{ order, reason, sentence }` |
| `GET /api/places?station=판교&category=cafe` | 반경 500m 장소 목록 (`cafe`, `food`, `play`), 가까운 순 최대 15곳 |

실패하면 `{ ok: false, reason }`을 돌려주며, 화면은 이 경우 기본 판결문이나 직접 입력으로 넘어갑니다.

## 폴더 구성

```text
src/            화면과 계산 (App, 순위·기존 방식 계산, 지도)
server/         API 서버 (Claude 호출, 주변 장소, 테스트)
server/data/    주변 장소 데이터 (30개 역)
PLAN.md         작업 계획과 역할 분담
STATUS.md       진행 상황과 발표 자료용 정리
```

## 한계와 다음 단계

- 이동시간은 직선거리를 바탕으로 한 추정치입니다(직선거리 × 2.5분 + 10분). 실제 지하철 노선과 환승을 반영하는 것이 다음 목표입니다.
- 주변 장소는 OpenStreetMap 데이터라 일부 가게가 빠져 있을 수 있습니다. 카카오 키를 넣으면 카카오 로컬 데이터를 씁니다.
- 약속 목적(밥·카페·술·공부)은 현재 판결문 문장에만 반영됩니다.
- 이후 계획: 막차 시간 반영, 약속 날짜 맞추기, 메신저 챗봇 연동, AWS Lambda 배포.
